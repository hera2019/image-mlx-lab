## 2026-09-24 · GPT 审查 Opus 5.5 的改动（提交 `3f697d4`、`3bdb3c3`）

GPT 的总体结论：这批修改保留，先补 1～3 三个小问题，再开始做效果图。
GPT 已确认过：发布检查通过；JS / Python / Shell 语法通过；网页访问不到 README、`server.log`、`.git`、`results/settings.json`、性能日志；伪造 Host 和跨站 POST 会被拒绝；大窗口下整页不滚动；右栏图片不被压扁。

### 1. 启动器可能继续使用旧版 server.py —— 已修改

**问题**：`Start-Image-MLX-Lab.command` 发现 18080 端口已有服务时直接打开页面。网页文件每次都从磁盘读新版，但正在运行的 Python `server.py` 可能还是更新前的旧代码。安全检查和模型管理都在 server 里，这一点很重要。

**处理**：
- `server.py` 启动时计算自身文件的 sha256 前 12 位，作为 `server_version`，由 `/api/status` 返回。用文件内容算，不用手动维护版本号，所以改了代码不会忘记改版本。
- 启动器会比较运行中的版本和磁盘上 `server.py` 的版本：
  - 不一致且空闲：只重启 Web 服务，模型保持运行，不用重新加载。
  - 不一致但有生成任务：不打断任务，只提示“任务完成后再双击启动一次”。
  - 更早的旧版 server 不返回版本号，也按“不一致”处理。
- 已验证：运行中的旧 server 被自动替换成新版；版本一致时再次启动不会重启。

### 2. 模型“加载中”时还能再次点“应用”切换 —— 已修改

**问题**：后端的切换锁在新模型进程启动后就释放了；前端只在 `switching` 时禁用“应用”，到了 `loading` 又能按，可能导致重复 stop/start、白等几分钟。

**处理**：
- 前端：`switching` 和 `loading` 时都禁用“应用”，按钮提示原因；有生成任务时也禁用。
- 后端也检查：模型处于 `switching` / `loading` 时，`POST /api/model` 返回 409“模型正在加载，请等它就绪后再切换”。即使前端被绕过，也不会重复切换。
- 已验证：切换进行中再发一次切换请求，返回 409；等就绪后切换正常。

### 3. 多标签页时，前端没有使用后端的 busy 状态 —— 已修改

**问题**：另一个标签页正在生成时，本页按钮仍显示可点，点了才被服务器 409 拒绝。

**处理**：
- 前端读取 `/api/status` 的 `busy`：别的标签页或窗口有任务时，“开始生成”和“AI 编辑选区”一起禁用，悬停提示是哪种任务，例如“其他标签页或窗口正在运行 AI 局部编辑任务”。模型设置里的“应用”也会禁用。
- 有别处任务时，状态每 2.5 秒刷新一次，任务一结束按钮就恢复；本页任务结束时也立即刷新一次。

### 4. README“本项目不用于商业用途”容易误解 —— 已修改

**问题**：代码是 MIT，而 MIT 允许商业使用；这句话会让人以为源代码也不能商用。

**处理**：README 的“许可证”一节改为分开说明：
- Image MLX Lab 源代码采用 MIT License；
- 默认使用的 Qwen-Image-2.1 模型受 Qwen Research License 限制，仅限非商业研究和评估；商业使用模型需要另行取得许可。

### 5. LICENSE 末尾附加了 Qwen 说明 —— 已修改

**问题**：内容没错，但 GitHub / SPDX 可能因此识别不出标准 MIT。

**处理**：`LICENSE` 恢复为纯 MIT 原文（Copyright (c) 2026 Houjun Co., Ltd.）。模型许可、mlx-serve 许可和生成内容责任移到新增的 `NOTICE`，README 也链接到它。

### 6. 发布检查只查历史路径，不查历史文本 —— 已修改

**问题**：GPT 手动扫描了 15 个提交的历史文本，没有发现本机用户目录的绝对路径、API key、token 或私钥；唯一命中的是检查程序自己的正则。但检查程序本身不会查。

**处理**：`scripts/check_public_release.py` 现在会扫描 Git 历史里**每一次新增的每一行**，检查个人绝对路径和疑似密钥；检查程序自身除外，因为它的正则本身就是在描述这种路径。
已在临时克隆里验证：提交一个含用户目录绝对路径的文件、再删除，检查仍会报出是哪个提交。当前真实仓库检查通过。

### 7. 效果图要放进仓库时的白名单 —— 已提前做好

**建议**：建 `docs/images/`，只放行白名单里的公开说明图；`results/` 里的用户图片和测试图一律禁止。

**处理**：
- 公开图片只能放在 `docs/images/`，而且文件名必须写进 `docs/images/APPROVED.txt`（已建好模板，目前为空）。
- 其他位置的任何图片、`docs/images/` 里未列入白名单的图片、`results/` 下的任何文件都会让发布检查失败。
- 白名单按“目录 + 文件名”判断：批准 `docs/images/main.png` 不会放行别处同名的 `main.png`。
- 已在临时克隆里验证这几种情况。规则也写进了 `PUBLIC_RELEASE.md`。

### 8. 本机 4-bit 没有编辑视觉模块 —— 不需要修改，属预期行为

GPT 的说明正确：8-bit 已装编辑视觉模块，4-bit 没有。用 8-bit 时指令编辑和 AI 局部编辑正常；切到 4-bit 时，界面会提示缺少约 1.1 GB 的模块，并给出补装命令。
这是按用户的决定设计的：视觉模块是可选下载，用户自己决定装不装。目前用户自己用 8-bit，4-bit 暂不补装。
